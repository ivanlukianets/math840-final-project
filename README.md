# 48 hours of solar and wind generation

MATH840 Time Series, final project, Kyiv School of Economics · Ivan Lukianets · November 2026

The task: forecast the 48 hours after the history (27 October 01:00 – 29 October 00:00, 2026) of the hourly
output of a solar and wind portfolio, each hour with a 95% prediction interval. Forecasts are scored with RMSE,
MAPE and the 95% Winkler score against a seasonal naive benchmark (daily season); the final ranking uses hours
25–48 only.

## The submitted forecast

`LUKIANETS_project.csv` is the average of two different kinds of model:

- **Timestral 209M**, a pretrained time-series foundation model with the weather as covariates and 32,768 hours of
  context;
- **LightGBM**, gradient boosting on the weather and the sun's position, forecasting log output relative to the last
  week's level, trained on two years.

On top of the average:

- a **night rule** for MAPE: a forecast below 100 is multiplied by 0.1;
- **Timestral's own 95% interval**, stretched where needed to contain the averaged point;
- after the public leaderboard, on 28 October only, the **lower bound at 09:00–14:00** raised to
  point − 0.7 · (point − lower bound). This is section 2.14 of the main notebook and the "After the public
  leaderboard" part of the report.

### How it was checked

Every model, about 560 variants, ran on the same **20 rolling windows**: one forecast origin every midnight from 6 to
25 October, each window forecasting 48 hours from the data before it. Scores are reported as **skill**: the score
divided by the seasonal naive's, so lower is better. Anything tuned on the windows' errors was tuned without the
scored window and its two neighbours, which share a day with it (purged leave-one-window-out).

| Day 2 (hours 25–48) of the 20 windows | RMSE skill | MAPE skill | Winkler skill | Coverage of the 95% interval | Windows beating the seasonal naive (RMSE / MAPE / Winkler) |
|---|---|---|---|---|---|
| the submitted forecast | 0.589 | 0.061 | 0.343 | 95.4% | 18 / 15 / 17 of 20 |

On the public leaderboard (27 October) the file scored RMSE 81.7, MAPE 38.2% and Winkler 741, against the seasonal
naive's 115.7, 84.3% and 521.

## How to run

Python 3.12:

```bash
pip install -r requirements.txt
```

**Reproduce the submission (about 20–30 minutes on a laptop).** The main notebook reads `train.csv`,
`weather_forecast.csv` and the other notebooks' saved results in `results/`. It writes `LUKIANETS_project.csv` and
the report's tables in `results/`. A clean copy of this folder reproduces the submitted file exactly.

```bash
jupyter nbconvert --to notebook --execute --inplace LUKIANETS_project_v2.ipynb --ExecutePreprocessor.timeout=-1
```

**The report (about a minute)** reads the data, the submission and `results/`:

```bash
jupyter nbconvert --to notebook --execute --inplace LUKIANETS_report.ipynb
```

**From scratch (optional).** Run the four family notebooks on a laptop and `LUKIANETS_project_colab.ipynb` on a
Colab GPU runtime. Each one rewrites its own files in `results/`. Then run the main notebook.

- The Colab notebook needs `NIXTLA_API_KEY` (TimeGPT) and `TABPFN_TOKEN` (TabPFN), from Colab secrets or a `.env`
  file next to it. Never commit that file; `.gitignore` excludes it.
- A model whose key is missing is skipped. A fresh GPU run can differ slightly from the saved results.

The series is disguised. Only the data given with the assignment were used.
